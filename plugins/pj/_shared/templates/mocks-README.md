# UI モック（索引）

こだわりの強い画面だけが持つ**体験の正**。方法論は pj プラグインの `_shared/visual.md` §V2。

> **運用は2行**
> 1. **モックがある画面は、モックを忠実に再現する。**
> 2. **デザインシステムが設定されていれば、語彙とトークンをそれに当てる。**
>
> 既定は「**全部再現**」。どこがこだわりかを実装者が察して拾い上げる作業は無い。
> DS を当てるとモックの意図が壊れる場合は、黙って妥協せず `design-language.md` に **DL-NN を1本足して記録**する。

## 置き場と構成のルール

```
docs/design/mocks/
  README.md                # このファイル（索引）
  <mock-id>/               # 1モック1ディレクトリ。<mock-id> は kebab-case（原則 feature 名）
    mock.md                # このモックの正
    index.html             # 開いてそのまま動く実体
```

- **実体はここに置く**（URL 参照だけにしない）。忠実に再現するには正確な列幅・閾値・算出式を読める必要がある。
- **埋め込みアセットは剥がす。目安 100KB / モック。** フォント・画像・DS バンドルは参照に留める。
- **原典（生成元の URL 等）は `mock.md` に必ず残す。**

## モックを作る基準

- ✅ spec が「この画面が最も作り込む」と宣言している
- ✅ 一覧 × 時系列 × 直接操作のように、テキストに落とすと失われるインタラクションがある
- ❌ CRUD フォーム・設定画面 → `design-language.md` の DL-NN だけで足りる。作らない
