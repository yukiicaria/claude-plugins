# src/components/ 作業時のルール（UI 実装の導線）

このディレクトリ（および UI を書くすべての場所）で守る。**pj の視覚の正は `docs/design/design-language.md`**。
ここはそれを UI 作業中に必ず目に入れるための導線（visual.md §V1 / DL-NN 規約）。

## まず確認: 取り込んだ出典はあるか

**`docs/design/intake/<intake-id>/` があれば、それがその成果物の追加基準**（visual.md §V2）。
書き始める前に `intake.md` と実体を読む。**拘束範囲は忠実度（fidelity）が決める**:

> `sketch` = 構造と並び順だけ ／ `structure` = 構造 ＋ 挙動 ／ `hifi` = 上記 ＋ 明記された寸法

- **部品と語彙は DS に当てる**（下記）。**部品が DS に置き換わるのは正常**で、
  **配置・列順・密度が変わるのは違反**。ここを取り違えない。
- **数値は `intake.md` の振り分け表から AC を辿る**。表に無い数値を実体から目測で拾わない。
- DS を当てると出典の意図が壊れるなら、**黙って折衷せず** `/pj:change` で `DL-NN` を1本足して記録する。

## デザインシステム: {{DS}}

- **部品は再発明しない。** UI は **{{DS}}** の語彙で組む。同等の部品があるのに生 HTML / 自作で作らない。
- **AI 向けドキュメント**: {{DS_DOCS}}（コンポーネント一覧・props・使い方。実装前にここを見る）。
- 共通コンポーネントは満たす原則を先頭コメントに `@satisfies DL-NN` で注釈する（grep で機械検証）。

## 単一窓口（勝手に発明しないための原則）

- **アイコン**: {{ICONS}} のみ。**生 `<svg>`・絵文字をアイコン代わりに使わない・別ライブラリを足さない**。
- **色**: トークン（{{TOKENS}}）のみ。**生の hex / rgb・Tailwind の任意値（`bg-[#...]`）を書かない**。
- **余白 / タイポ / 角丸 / 影**: スケール / トークンに従う（場当たりの px を散らさない）。

> ここは確率的な導線。最終的な整合は review/audit の **`pj:design-reviewer`**（concepts §14）で確認する。
> 詳しい方法論は pj プラグインの `_shared/concepts.md`。視覚の正を直すときは `/pj:design` か `/pj:change`。
