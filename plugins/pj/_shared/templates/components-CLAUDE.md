# src/components/ 作業時のルール（UI 実装の導線）

このディレクトリ（および UI を書くすべての場所）で守る。**pj の視覚の正は `docs/design/design-language.md`**。
ここはそれを UI 作業中に必ず目に入れるための導線（visual.md §V1 / DL-NN 規約）。

## まず確認: その画面にモックはあるか

**`docs/design/mocks/<mock-id>/` があれば、それがその画面の「体験の正」**（visual.md §V2）。
書き始める前に `mock.md` と `index.html` を読む。運用は2行:

> 1. **モックを忠実に再現する。**
> 2. **語彙とトークンは下の {{DS}} に当てる。**

- **既定は「全部再現」。** 配置・列順・固定/可変・密度・寸法を「どこがこだわりか」で選り分けない。
- **挙動は落としやすい**（ピンチ / ⌘+wheel ズーム / スクロール同期 / 段階的開示の閾値 /
  オーバーレイの反転）。実装したら `@satisfies <mock-id>-UX-NN` を注釈し、
  **`mock.md` の全 UX-NN に注釈があること**を grep で確かめる。落ちても静止画では気づけない。
- **DS を当てるとモックの意図が壊れる**箇所が出たら、黙って折衷せず `/pj:change` で DL-NN を1本足して記録する。
- モックが**無い**画面は、下の DS ルールと `design-language.md` の DL-NN だけで組む（モックが無いのが普通）。

## デザインシステム: {{DS}}

- **部品は再発明しない。** UI は **{{DS}}** の語彙で組む。同等の部品があるのに生 HTML / 自作で作らない。
- **AI 向けドキュメント**: {{DS_DOCS}}（コンポーネント一覧・props・使い方。実装前にここを見る）。
- 共通コンポーネントは満たす原則を先頭コメントに `@satisfies DL-NN` で注釈する（grep で機械検証）。

## 単一窓口（勝手に発明しないための原則）

- **アイコン**: {{ICONS}} のみ。**生 `<svg>`・絵文字をアイコン代わりに使わない・別ライブラリを足さない**。
- **色**: トークン（{{TOKENS}}）のみ。**生の hex / rgb・Tailwind の任意値（`bg-[#...]`）を書かない**。
- **余白 / タイポ / 角丸 / 影**: スケール / トークンに従う（場当たりの px を散らさない）。

> ここは確率的な導線。最終的な整合は review/audit の **`pj:design-reviewer`**（concepts §7）で確認する。
> 詳しい方法論は pj プラグインの `_shared/concepts.md`。視覚の正を直すときは `/pj:design` か `/pj:change`。
