# docs/specs/ 作業時のルール（pj:spec レイヤー）

このディレクトリは pj パイプラインの **WHAT レイヤー**（要件仕様）。編集時は必ず守る:

- **何を・どう振る舞うか**だけを書く。実装詳細（ライブラリ・関数設計・SQL スキーマ）は書かない（→ docs/design/）。
- 成果物を直したら **frontmatter の `updated` を今日の日付**にし、末尾 `## 変更履歴` に1行追記する。
- **用語は docs/specs/glossary.md に従う**。新しい概念語を導入したら glossary も更新する。
- **受入条件は検証可能な粒度**で書く（build で test に 1:1 で写す契約）。
- 前提を覆して書き直したら、古い前提を参照している**他 feature の記述も追って直す**。
- progress / build_progress は**実態に合わせて毎回つけ直す**（見栄えで高く維持しない）。

詳細な方法論は pj プラグインの `_shared/concepts.md`。仕様を育てるときは `/pj:spec` を使う。
