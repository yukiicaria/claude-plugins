# docs/design/ 作業時のルール（pj:design レイヤー）

このディレクトリは pj パイプラインの **HOW レイヤー**（技術設計）。編集時は必ず守る:

- ここは「どの技術で・どんな構造で」を決める層。**WHAT（振る舞い）は docs/specs/ が正**で、ここでは変えない
  （振る舞いを変えたくなったら **`/pj:change`** に投げる。正レイヤーの判定と下流への伝播はそちらが引き受ける）。
- **モックのある画面**（`mocks/<mock-id>/`）は、モックが**その画面の体験の正**。実装は忠実に再現し、
  DS があれば語彙とトークンをそれに当てる（visual.md §V2）。
- **エンティティ名・識別子は docs/specs/glossary.md に従う**。spec の概念と双方向にトレースできるようにする。
- 大きな選定は **adr/ に1件ずつ決定記録**を残す（理由が後から辿れること）。
- spec が「実装裁量」と投げた**横断項目は conventions.md で1回だけ決め、全 feature で統一**する。
- 成果物を直したら `updated` を今日の日付にし、`## 変更履歴` に1行追記する。

詳細な方法論は pj プラグインの `_shared/concepts.md`。設計を詰めるときは `/pj:design` を使う。
