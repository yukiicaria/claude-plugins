# pj — 視覚の正と、外部成果物の取り込み（UI を持つプロジェクトのみ）

> `concepts.md` が **5スキル共通の背骨**であるのに対し、このファイルは **UI を持つプロジェクトだけ**の出典。
> **CLI 等 UI の無いプロジェクトでは誰も読まない**（design-language を N/A 宣言して終わり）。
>
> **読むスキル**: `/pj:setup`（DS 導入 = §V1 の3スロット契約）／`/pj:design`／`/pj:build`（UI 実装時）／
> `/pj:change`（UI に触れる変更時）。**`/pj:spec` は読まない**（WHAT に視覚は含まれない）。
>
> ID 規約（`DL-NN` の形式・採番者・不変ルール）の正は **`concepts.md` §4**。ここには書かない。

## §V1. design-language — 全画面共通の視覚の正

glossary が**用語の正**であるのと対称に、`docs/design/design-language.md` が**視覚の正**。spec から導出し
（design フェーズ）、全画面・全コンポーネントが従う。整合は **design-reviewer**（concepts §14）で監査する。
**root product が所有し、UI を持つ package も準拠する**（package ごとに持つと DS が割れる・concepts §3）。

**デザインシステムの 3スロット契約（DS 非依存）**: 視覚の共通化は特定 DS に依存しない3スロットで担保する。
`/pj:setup` がこれを各 DS（または preset）に当てはめて配線する:

- **実体** … 部品とトークンの本体（DS パッケージを install／preset は最小トークンを scaffold）
- **導線** … `src/components/CLAUDE.md` に DS の AI ドキュメント（llms.txt 等）を指すポインタ。UI 作業時に
  **自動ロード**され「ルールが向こうから来る」を成立させる（Claude が勝手にアイコン・色を発明しない導線）
- **正の宣言** … design-language §F に「**語彙・トークンの正 = <DS>**」を固定。DS があれば DL-NN はその差分だけ、
  preset は DL-NN が全部を担う。**プリミティブ族（アイコン筆頭・色・日付/数値書式 等）は単一窓口**を決め再発明させない

> 当面、生 color / 生 svg / 別ライブラリの **lint ブロック強制は入れない**（まず warning、ブロックは規律が
> 固まってから）。導線（上記）＋ audit の `pj:design-reviewer` で運用する。

## §V2. intake — 外部の設計成果物を取り込む

design-language（§V1）は**全画面横断**の原則を持つ。しかし「この部品の行高は何 px か」「どの列を固定するか」
「ポップオーバーをどこに寄せるか」は**その成果物固有**で、一行原則に圧縮すると必ず失われる。そこを担うのが intake。

**外から来た設計成果物**（Artifact のエクスポート・ハンドオフ・スクリーンショット・API 設計書）をリポジトリに
取り込み、**pj の ID（AC-NN / DL-NN）に振り分けて正にする**のが仕事。

### 3つの立場を混ぜない

| 立場 | 何か | 拘束力 |
|---|---|---|
| **正** | 振り分けて ID を振ったもの（AC-NN / DL-NN） | **ここだけが拘束する** |
| **出典** | 取り込んだ実体（HTML・画像・設計書）。リポジトリに残す | 参照される。直接は拘束しない |
| **参考** | 同梱の参考実装・型定義（`reference/*.tsx` 等） | **意図を読むためだけ。写経しない** |

**参考実装をコピーしない。** ルーティング・状態管理・命名は実装先の作法に合わせる。ハンドオフ側も普通そう
明記している（「そのまま本番に入れるコードではない」）。守らないと、出典のフレームワーク前提がそのまま
持ち込まれ、**その repo の作法が壊れる**。

### 忠実度（fidelity）— 塩梅はここで決まる

**入力は多様で、取れる情報量が違う。** 何を約束するかを取り込み時に宣言し、それが実装の拘束範囲になる。

| fidelity | 典型的な入力 | 実装が拘束されるもの |
|---|---|---|
| `sketch` | スクリーンショット・手書き・ラフ | **構造と並び順だけ。** 数値は拾わない |
| `structure` | 動くプロトタイプ（寸法の根拠は無い） | 構造 ＋ 挙動。見た目は DS に委ねる |
| `hifi` | 数値つき設計書・トークン準拠のプロトタイプ | 上記 ＋ **明記された寸法・閾値・時間** |

- **宣言は出典側の申告を尊重する**（ハンドオフが `High-fidelity` と書いていれば `hifi`）。
- **`sketch` に数値を求めない。** スクショから px を測って AC にするのは**捏造**。
- **`hifi` で数値を落とすのは落第。** 明記された数値は AC に写す（振り分け表で追える）。
- 迷ったら**低いほうを宣言する**。後から上げるのは安いが、守れない約束は高くつく。

### 置き場と構成（product ごとに持つ）

```
<product>/docs/design/intake/
  README.md              # 索引: 何を取り込んだか（1件1行）
  <intake-id>/           # kebab-case
    intake.md            # この取り込みの正（出典・fidelity・振り分け表・拾わなかったもの）
    <実体>               # index.html / screenshot.png / api.md など。開いて読める状態で
```

- **`<intake-id>` は成果物の名前**（`data-table` / `sidebar-nav`）。feature 名に縛らない。
- **実体はリポジトリに置く**（URL 参照だけにしない）。忠実に再現する以上、正確な寸法・閾値・算出式を読める
  必要があり、URL は安定して読めない。**原典（Artifact の URL 等）は `intake.md` に必ず残す。**
- **同梱アセットは剥がす。目安 100KB / 件**（実測: 380KB の DS バンドルが2箇所に重複していた例がある）。

### 振り分けが仕事 — 行き先は2つしかない

| 出典の記述 | 判定 | 行き先 |
|---|---|---|
| 「compact の行高は 39px」「デバウンス 250ms」「1100px 未満は priority≤2 まで隠す」 | **テストできる** | **AC-NN**（その product の spec） |
| 「影は使わない・角丸は一律 4px」「トークンは `--oy-*` をそのまま使う」 | **横断の原則** | **DL-NN**（root の design-language） |
| 「余白と配置」 | 見比べれば分かる | **ID を振らない**。実体との突き合わせで足りる |

- **判定は「テストできるか」1つ。** できるなら AC、できず横断なら DL、どちらでもないなら振らない。
- **数値だから DL、ではない。**「行高 39px」は検証できるので振る舞い（AC）。「影を使わない」は全画面に効くので DL。
- **intake はどこに落とすかを決めるところまで。採番の規律は変えない**（採番者は concepts §4）。

### 拾わなかったものを必ず残す

`intake.md` に「**拾わなかったもの と 理由**」を書く。書かないと、次に読む人が「見落としたのか、意図的に
外したのか」を区別できない（例: fidelity が `sketch` なので数値を拾わなかった／出典の FW 前提なので実装先の
作法に置き換えた／将来やる（v2 と明記されている））。

### 未描画 ≠ 否定（最大の落とし穴）

出典は**ハッピーパスのダミーデータ**で作られる。**エラー状態・空状態・権限による非表示・バリデーション・
確認ダイアログ**は描かれないのが普通。

**出典に描かれていないことは「否定」ではなく「未描画」が既定。** ここを取り違えると、受入条件が静かに実装から
消える（最も起きやすい事故）。既存 AC を廃止すべきだと判断したら、**必ず確認してから `/pj:change`（L2）で
spec から直す**。

### 差し替え（作り直したとき）

実装を見て「これは違う」となり、出典を作り直して当て直すのは正常な経路。**既に AC・DL・テスト・実装がある
状態への上書き**なので、新規取り込みとは手順が違う（**手順の正は `/pj:design` の「差し替え」**）。原則は3つ:

- **高度は既定 L3**（HOW が変わる・WHAT は不変・concepts §16）。振る舞いに触れるなら L2 に上げる。
- **旧版は git 履歴に残る**ので実体は上書きしてよい。ただし `intake.md` の「出典」は**世代を積む**。
- **ID は振り直さない。** 残るものは同じ ID を維持、消えたものは欠番、増えたものは新番（concepts §4）。

### 上流との関係

intake は **design レイヤーの成果物**。取り込む過程で**振る舞い（WHAT）の誤り**に気づいたら、ここで辻褄を
合わせず `/pj:change` に投げて spec に戻す（concepts §8・§16）。**出典が spec を鍛えるのは正常な経路。**
